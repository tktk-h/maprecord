# 旅行（日をまたぐまとまり）Design

**日付:** 2026-08-29 / **版:** 20260827s

## なぜ

3泊の旅行が、カレンダーでもルートでも「バラバラな3日」にしか見えなかった。
`#タグ` と期間ふりかえりで近いことはできたが、**旅行そのもの**がデータに無かった。

## 決め方：記録には何も足さない

```
spaces/{id}.trips = [ { id, label: '沖縄旅行', start: '2026-08-10', end: '2026-08-13' } ]
```

**「記録の日付が期間に入っていれば、その旅行の記録」** とだけ決める。
記録の側に旅行IDを持たせない。こうすると：

- 旅行中に足した記録も、帰ってから足した記録も、日付さえ合えば**勝手に入る**
- 既存の記録は1件も書き換えずに済む（22件の移行が不要）
- 期間を直せば、中身も自動でついてくる

代償は「同じ日を2つの旅行に入れられない」こと。重なりは保存時に弾く
（ある日が2つの旅行に属すると、帯も「何日目」も意味が壊れるため）。

## 作ったもの

| | どこ | 中身 |
|---|---|---|
| 判定 | `js/trips.js` | 期間内か・何日目か・何泊何日か・重なり検査。純粋関数＋自己テスト24件 |
| 編集 | `js/trip-edit.js` | 設定 →「旅行」。一覧／追加／編集／削除。期間はふりかえりの期間カレンダーを流用 |
| 帯 | `js/calendar.js` | 旅行の日のマス上端に線。記録の無い日も薄く塗る。月の見出しの下に旅行チップ |
| 絞り込み | `js/records.js` `focusTrip()` | 期間フィルタに落とし込み、地図をその旅行ぜんぶが入る範囲へ |
| 流れ | `js/records.js` `showTripRoute()` | 「◯◯の流れ」。1日目・2日目…で区切る。日の見出しを押すとその日のルート（並べ替えはそちら） |

「旅行を見ている」状態は**絞り込みの期間が旅行と一致しているか**で判定する。
旅行モードという別の状態を持たない＝既存の絞り込み・× の作法がそのまま効く。

## 確かめたこと（実ブラウザ）

- 帯：8/10〜8/13 の4日に付き、記録の無い 8/12 にも付く。旅行外の 8/20 には付かない
- 旅行名に `<img onerror=...>` を入れても文字として出る（esc 済み）
- 流れ：記録の無い3日目は飛ばして 1日目→2日目→4日目。同じ日の中は order 順
- 期間外（8/20）の記録は流れにも地図にも入らない

## やらなかったこと

**ふりかえりの旅行プリセット**。期間ふりかえりで同じ日付を選べば同じものが作れるので、
欲しくなってから足す。
