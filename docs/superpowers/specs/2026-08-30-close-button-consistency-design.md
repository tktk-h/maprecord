# 「閉じる」を揃える Design

**日付:** 2026-08-30 / **版:** 20260827v（実装時に上げる）

## 何をする変更か

アプリ中の「閉じる」を **右上の丸い×** ひとつに揃え、**当たり判定を44pxにする**。
覚えることを「閉じるはその画面の右上」の1つだけにする。

## なぜ必要か

本人の言葉:「×ボタンの位置が機能によってばらばらだったり、なんか全体的に使いづらい」。
数えたら、同じ「閉じる」に **大きさ5種類・置き場所4種類** あった。

| 画面 | クラス | 置き場所 | 大きさ |
|---|---|---|---|
| 写真のライトボックス | `.lb-close` | 画面の右上 | 44px |
| ふりかえりのスライド | `.rv-x` | 画面の右上 | 34px |
| 設定 | `.set-x` | カードの右上 | 32px |
| ジャンル編集・旅行編集 | `.ge-x` | カードの右上 | 32px |
| 下シート | `#sheet-close` | シートの右上 | 30px |
| 思い出カード | `.mem-x` | カードの中 | 24px |
| ふりかえりカード | `.rv-card-x` | カードの中 | 24px |
| ふりかえりの期間ピッカー | `.rv-close` | **一番下の横長ボタン「閉じる」** | 文字 |
| ポスタープレビュー | `.pv-close` | 下のピル型ボタン「閉じる」 | 文字 |
| まとめて追加 | `.bulk-x` | **画面の左上**・`✕` の文字 | font 20px |

**特に異物**が3つある。期間ピッカーだけ一番下の文字ボタン（同じ「ふりかえり」の中でスライドは右上の×
なのに閉じ方が変わる）。まとめて追加だけ左上。この2つはアイコンですらない。

**もうひとつ、どれも小さい。** 指で押すものは44pt以上が目安だが、44pxあるのはライトボックスだけで、
残りは24〜34px。思い出カードの×は推奨の半分強しかない。「押しづらい」の正体はこれ。

## 設計

### 共通クラス `.x-btn` をひとつ作る

- **見た目は 32×32px の丸**（今の多数派に合わせる）
- **当たり判定は 44×44px**。透明な `::after`（`position:absolute; inset:-6px`）で広げる
- 色は既存のまま `--surface-2` / `--text-muted`
- 写真やポスターの上に載るものだけ `.x-btn.on-dark` で白系（ライトボックス・ポスタープレビュー）

**見た目を44pxにしない理由**: 思い出カードやふりかえりカードは小さく、44pxの丸を置くと×が
カードの主役になってしまう。**見た目は揃え、当たり判定だけ広げる**ことで、統一と押しやすさを両立する。

### 位置は2種類だけ。中身が決める

- **画面の右上**（`.x-btn.x-fixed` = `position:absolute; top: calc(14px + var(--safe-top)); right:14px`）
  — ふりかえりスライド、期間ピッカー、ポスタープレビュー、ライトボックス、まとめて追加
- **カード／シートの右上** — 設定、ジャンル編集、旅行編集、下シート、思い出カード、ふりかえりカード

判断の基準は「**画面いっぱいに出るものか、何かの上に乗るカードか**」。迷いようがない分け方にする。

### なくすもの

- `.rv-close`（期間ピッカーの一番下の「閉じる」）→ 右上の×にする
- `.pv-close`（ポスタープレビューの「閉じる」ピル）→ 右上の×にする。
  下のボタンは**「共有・保存」だけ**になり、主役がはっきりする
- `.bulk-x` の**左上**の位置と `✕` の文字 → 右上へ移し、他と同じ Phosphor アイコンにする

### 触らないもの

- `#search-clear`（検索を消す）と `#filter-clear-top`（絞り込みをリセット）。
  これは「**消す**」であって「閉じる」ではない。混ぜると意味が濁る。
- `.rb-x`（ふりかえりに戻る帯の×）。帯の一部なので丸にはしない。
  ただし**当たり判定だけ44px**に合わせる。押すと絞り込みも戻る動きは変えない（[[maprecord-x-undoes-its-filter]]）。
- 閉じたときの挙動そのもの。今回は見た目と当たり判定だけで、何が起きるかは一切変えない。

### 実装時の注意

**`overflow: hidden` の親に注意。** 当たり判定を `::after` で外側へ広げるので、親が
`overflow:hidden` だと**はみ出した部分が切り取られ、当たり判定が広がらない**（見た目は変わらないので
気づけない）。調べた結果、`overflow:hidden` を持つのは `#panel`（スマホ幅）と `#panel-content` の2つだけ。
`#sheet-close` は `#panel-content` の**外**にあり、上10px・右12px なので6px 広げても `#panel` の中に収まる。
`#memory-card` `#review-card` `.rv-picker` などに `overflow` の指定は無い。**現状どこも切られない。**
将来ここに `overflow:hidden` を足すと当たり判定が黙って縮むので、検査で見張る。

**期間ピッカーは「閉じる」が2箇所ある。** 記録が0件のときの画面にも同じ `.rv-close` がある。
両方とも右上の×にする。

## 触るファイル

- `style.css` — `.x-btn` を新設し、上表の10個の指定をそれに寄せる
- `index.html` — `#sheet-close` `.set-x` にクラスを足す
- `js/review-ui.js`（`.rv-x` `.rv-card-x` `.rv-close` `.pv-close`）、`js/genre-edit.js`・`js/trip-edit.js`（`.ge-x`）、
  `js/memories.js`（`.mem-x`）、`js/lightbox.js`（`.lb-close`）、`js/bulk.js`（`.bulk-x`）、`js/app.js`（`#sheet-close`）

## どう確かめるか

**目視では判定しない**（[[maprecord-ios-fullscreen]] の教訓）。z-index のときと同じく、
ローカルにサーバを立てて実ブラウザで `getComputedStyle` を測る:

- すべての閉じるボタンが `.x-btn` を持つ
- `.x-btn` が 32×32px の丸に計算される
- `::after` が `inset:-6px` ＝ 当たり判定が 44×44px になる
- `.x-fixed` が付いたものだけ `position:absolute` で右上に来る

最後の見え方（カードの中で浮いていないか等）は本人がスマホの本番URLで確認する。
