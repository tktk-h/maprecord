# 一括カードの折りたたみ＋メモ欄＋個別保存 Design

**日付:** 2026-08-19
**対象:** `js/bulk.js`（一括追加「まとめて」画面）＋ `style.css`

## Goal
一括確認画面のカードを**折りたたみ可能**にし、**メモ欄**と**カードごとの個別保存**を追加する。狙いは、AIが店名を裏で推測している間もユーザーが待たずに編集（メモ書き・場所指定・個別保存）を進められること。カードが増えても縦に長くなりすぎないよう、既定で全カードを畳んでおく。

## 背景
- 一括確認画面（`js/bulk.js`）は写真をグループ化して1グループ=1カードで表示し、「すべて保存」で一括作成する。
- 各カードのAI提案（Gemini）は1件あたり10〜30秒かかるため、待ち時間に別カードを編集したい。
- 普通の追加（`records.js`）には「メモ・感想」欄があるが、一括保存では `memo: ''`（空）で保存していた。

## 決定事項（すり合わせ済み）
- 開閉操作：**畳んだ時は「写真＋名前の帯」をタップで開く／開いた時はカバー写真タップで畳む**。入力欄・各ボタンは開閉トリガーにしない。
- 畳み時の「ここで分割」：**畳んでいる間は非表示**（分割は写真選択が要るため、開いた時だけ表示）。
- 個別保存の成功後：**そのカードはリストから消える**（＝既存「すべて保存」と同じ挙動）。
- 追加する入力欄：**メモ欄のみ**（タグは追加しない）。

## データモデル（グループに追加するフィールド）
グループ生成箇所（`handleFiles` の `added`／`doSplit` の `newG`）に2つ追加：
- `collapsed: true` — 既定で畳んだ状態。
- `memo: ''` — メモ本文。

既存フィールド（`candidates` / `aiState` / `aiPickId` など）は変更なし。

## カードの2状態

### 畳んだ状態（collapsed=true）
表示するもの：
- カバー写真（小）＋ 店名（未入力なら「（店名未入力）」）＋ 日付・枚数
- 未入力強調：`isSaveable(g)` が false のとき、オレンジ枠＋⚠️バッジ（既存の `incomplete`/`bulk-badge` を流用）
- `aiState==='loading'` の時は小さく「AI判定中…」表示
- ボタン列：**↑前と結合**（先頭カード以外）／**🗑削除**／**💾保存（この1件）**
- 「写真＋名前の帯」領域が開閉のタップ対象（ボタン列は対象外）

表示しないもの：名前入力欄・AI候補チップ・場所ボタン・ジャンル/日付/メモ・写真ストリップ・ここで分割。

### 開いた状態（collapsed=false）
現状の全内容 ＋ 追加：
- 既存：名前入力・AIエリア（候補チップ/AI判定中/提案ボタン）・場所行（店名で検索/地図でピン/状態）・ジャンル・日付・写真ストリップ・分割ヒント・前と結合/ここで分割/削除
- **追加：メモ・感想 textarea**（ジャンル/日付の下）
- **追加：この1件を保存 ボタン**（カード末尾）
- カバー写真タップで畳む

## 開閉の実装
- `refreshCard(i)` は `g.collapsed` を見て畳み/開きどちらのHTMLを描画する（`cardHtml` を状態分岐）。
- タップ配線（`wireCards`）：
  - 畳み時のヘッダー（`.bulk-head`）`onclick` → `g.collapsed=false; refreshCard(i)`。
  - 開き時のカバー写真（`.bulk-cover`）`onclick` → `g.collapsed=true; refreshCard(i)`。
  - ボタン・入力欄は従来通り各自の `onclick/oninput`（開閉は発火しない）。
- 既定は全カード `collapsed:true`。分割で増えたカードも `collapsed:true`。

## メモ
- 開いた状態に `<textarea class="bulk-memo" data-i>`（プレースホルダは普通の追加に合わせる）。
- `wireCards`：`.bulk-memo` の `oninput` → `groups[i].memo = 値`（1文字ごとに状態へ反映＝再描画で消えない）。
- 保存時（`doSave`・個別保存）：`memo: g.memo || ''` を `App.cloud.add` に渡す（現在の `memo:''` を置き換え）。

## 個別保存
- 1グループ保存の共通処理を `saveGroup(g, allRecords, progressCb)` に抽出し、`doSave`（全件ループ）と `saveOne(i)` の両方から使う。既存 `doSave` の写真アップロード（`toStoredMany`）→`cloud.add`→プレビューURL解放の流れを踏襲。
- `saveOne(i)`：`isSaveable` を満たす時のみ実行。成功したら `groups` から該当を除去し `renderReview()`。失敗時は `alert` で通知しカードは残す。
- 個別保存ボタン：`isSaveable(g)` が false の間は `disabled`。畳み時・開き時の両方に表示。
- 既存「すべて保存」ボタンは存置（残りの保存可能グループを一括保存）。

## AI処理中の編集の両立
- AI（`autoSuggestAll`→`aiSuggest`）はバックグラウンドで動作し、**空の名前欄が埋まる時だけ**グループを更新（メモや他入力は触らない）。
- メモは `oninput` で `g.memo` に即保存されるため、AI完了による再描画でも本文は保持される。
- ユーザーが開いて編集しているカードを邪魔しないため、`aiSuggest` の状態更新時、そのカードが**開いている（`collapsed===false`）場合はカード全体を作り直さず**、名前欄の値・AI判定中表示・枠/バッジのみを差分更新する。**畳んでいる（`collapsed===true`）カードは従来通り `refreshCard` で全描画**する。この判定は `g.collapsed` の真偽のみで行い、フォーカス状態の検出は使わない。

## スタイル（`style.css` 追加）
- 畳みカードのヘッダー（`.bulk-head`：写真＋名前＋メタを横並び、タップ可能に見せる）。
- 畳み時のボタン列（`.bulk-collapsed-acts`）。
- 個別保存ボタン（`.bulk-savecard`：保存可能＝緑系アクセント、無効＝グレー）。
- メモ欄（`.bulk-memo`）は既存フォーム要素のトーンに合わせる。
- 既存の `incomplete`/`bulk-badge`/`bulk-cands` 等は流用。

## テスト方針
自動テストランナー無し。`node --check js/bulk.js` の構文チェック＋本人の実機確認：
- 開いた直後、全カードが畳まれている。
- 帯タップで開く／カバー写真タップで畳む。入力欄・ボタンでは開閉しない。
- 畳み時に写真・名前・前と結合・削除・保存が出る（分割は出ない）。未入力はオレンジ枠＋バッジ。
- メモを書ける。AIが裏で名前を埋めてもメモは消えない。
- 個別保存でその1件だけ保存され、カードが消える。メモも記録に入る。
- 「すべて保存」も従来通り動く。

## 非対象（YAGNI）
- タグ入力の追加（メモのみ）。
- 折りたたみのアニメーション（無くても可、任意）。
- 並び替えや複数選択などの新規操作。
