# 期間ふりかえり（年に限らないふりかえり）設計

2026-08-25

## 背景と目的

「ふりかえり」は現在すべて暦年単位で作られている。`computeYearReview(all, year, ...)`、12か月固定の棒グラフ、年ピッカー、ポスター中央の巨大な年号まで、年が前提に埋め込まれている。

一方、実際に見返したい単位は年だけではない。旅行の数日間、これまでの全記録——そうした期間もひとまとまりとしてふりかえりたい。

本設計は、ふりかえりの対象を「年」から「期間（period）」へ一般化する。年のふりかえりは、その期間の一種として扱う。

## スコープ外（今回やらないこと）

- **期間の名前付き保存・再利用**：「沖縄旅行」を記録に紐づけて永続化し、後から一覧で選び直す仕組みは作らない。期間はその都度指定する使い捨て。
- **「訪れた場所」の数え方の変更**：`count` はピン本数のままで、同じ店に3回行けば3か所と数える。これは語感を優先した既存の意図的な選択（`docs/superpowers/specs/2026-08-24-year-poster-share-design.md`）であり、本件で変更しない。
- **後方互換シム**：`computeYearReview` を残して新関数から呼ぶ、といった二重構造は作らない。呼び出し側（stats / ui / poster / 年末カード）をすべて period 形式へ移行する。

## 期間モデル

すべての集計・表示は次のオブジェクトを起点にする。

```js
period = {
  kind: 'year' | 'range' | 'all',
  start: 'YYYY-MM-DD',   // 含む
  end:   'YYYY-MM-DD',   // 含む
  label: string,          // 見出しに使う文字
}
```

`App.reviewStats` に3つの生成関数を置く。

| 関数 | kind | start | end | label |
|---|---|---|---|---|
| `makeYearPeriod(y)` | `year` | `y-01-01` | `y-12-31` | `String(y)` |
| `makeAllPeriod(all, today)` | `all` | 最古の記録日（記録が無ければ today） | 最新の記録日と today の遅い方 | `'これまで'` |
| `makeRangePeriod(start, end, label)` | `range` | 引数 | 引数 | 入力が空なら `formatRangeLabel(start, end)` |

`makeAllPeriod` の終了日を today で止めず最新の記録日まで伸ばすのは、先の日付で入れた記録が「これまで」から黙って消えないようにするため。

`formatRangeLabel(start, end)` は日付範囲を短く表す。同じ年なら `3/1〜3/5`、年をまたぐなら `2025/12/30〜2026/1/3`。

`formatDateLine(period)` はポスター・総集編に添える控えめな日付行を作る。同じ年なら `2026.3.1 〜 3.5`（右側は年を省く）、年をまたぐなら `2025.12.30 〜 2026.1.3`。

この行は**見出しが言っていないことを補う**ためにある。見出しがすでに日付を語りきっているときは出さない。

| 見出し | 日付行 | 理由 |
|---|---|---|
| `2026`（年） | 出さない | 見出しが年号そのもの |
| `2025/12/30〜2026/1/3`（自動・年またぎ） | 出さない | 見出しと同じ内容をなぞるだけになる |
| `3/1〜3/5`（自動・同年） | 出す | 見出しに年が無いので、この行が年を補う |
| `沖縄旅行`（自分で入力） | 出す | 見出しに日付が無い |
| `これまで` | 出す | 見出しに日付が無い |

判定のため `makeRangePeriod` は `autoLabel`（見出しが日付そのものか）を period に持たせる。

この規則は最初の設計には無く、実際に生成したポスターを見て初めて必要だと分かった（年またぎの自動ラベルで大見出しと小さい日付行が同じ文字列を二度出していた）。

## 集計の一般化

`computeYearReview(all, year, anniversary, today)` を `computePeriodReview(all, period, anniversary, today)` に置き換える。対象記録の絞り込みは `period.start <= r.date <= period.end`。

戻り値は既存のフィールドを引き継ぎ、次の3点が変わる。

**`period`** を戻り値に含める。表示側が kind と label を参照するため。

**`monthlyCounts` / `busiestMonth` → `buckets` / `busiest`**。暦月は年専用の概念なので、期間の長さで刻みを切り替える。

```js
buckets = { unit: 'month' | 'year', items: [{ key, label, count }] }
busiest = { label, count } | null
```

- 期間が366日以内（`start` と `end` の両端を含む日数）→ `unit: 'month'`。開始月から終了月まで、期間が実際にまたぐ月だけを並べる（年のふりかえりなら1月〜12月の12個になり、現状と一致する）
- 366日を超える → `unit: 'year'`。開始年から終了年まで
- `count` は既存どおり「おでかけ日数」（同じ日に何か所まわっても1日）
- バケットが1つしかない期間（同月内の旅行など）では棒グラフと `busiest` を出さない。棒が1本のグラフは情報を持たないため、`busiest` は `null` を返す
- `busiest` は現状の `busiestMonth` と同じく、最大値が2以上のときだけ返す

**`newPlaces`（はじめての場所）の判定を日付ベースにする**。現在は「その場所の初訪問の"年"が対象年か」で判定しているため、年内の短い期間では常に0になってしまう。全記録から場所ごとの初訪問日 `firstDate` を求め、`firstDate >= period.start` なら新規とする。年の期間ではこの判定は既存ロジックと一致する（対象記録である以上 `firstDate <= period.end` は自明のため）。

**`daysTogether`（付き合って◯日目）の基準日**は `min(period.end, today)` とする。過去の期間ならその期間の終了日、現在進行中なら今日。期間全体が記念日より前、または期間全体が未来なら `null`。年の期間では既存の挙動（過去年は12/31、今年は today、未来年は null）と一致する。

## 入口UI（年ピッカーの拡張）

`showPicker()` を「どの期間をふりかえる？」に改める。既存の年ボタン一覧に2つ加える。

**「これまで」ボタン** — `makeAllPeriod` で開く。

**「期間を選ぶ」ボタン** — 押すとその場に入力フォームが開く。

- 開始日 / 終了日（`<input type="date">`）
- 見出しの文字（`<input type="text" maxlength="10" placeholder="沖縄旅行">`、任意）
- 「見る」ボタン

検証はフォーム内にメッセージを出し、ピッカーを閉じない。

| 条件 | メッセージ |
|---|---|
| 開始日または終了日が空 | 「期間を選んでね」 |
| 開始日 > 終了日 | 「開始日と終了日が逆だよ」 |
| その期間に記録が0件 | 「この期間の記録はまだないみたい」 |

見出しの文字は10文字までとする。これはポスター見出しが1行に収まる上限（後述の下限フォントサイズ72pxで920px幅に10全角文字が収まる）から決めた値。空欄なら `formatRangeLabel` の自動生成を使う。

## 件数しきい値

記録が3件未満のとき「まだ少なめ」画面を出す既存の扱い（`isSparse`）は、`kind === 'year'` のときだけ残す。`range` / `all` は件数によらずスライドショーを出す——期間を自分で選んだ時点で「これを見たい」という意思が明確だから。中身の無いスライドが自動で落ちる仕組み（`planSlides`）は従来どおり働くので、記録1件でも破綻しない。

記録が0件の期間は `range` では開かない（上記の検証で弾く）。年ピッカーには記録のある年しか並ばないので、`year` で0件になることもない。

## 文言の一般化

見出しは常に `period.label` を使う。ユーザー入力を含むので、HTML に差し込む箇所ではすべて既存の `esc()` を通す。

| 箇所 | year | range / all |
|---|---|---|
| スライド「訪れた場所」の見出し | 今年訪れた場所 | 訪れた場所 |
| スライド「濃かった月/年」 | いちばん濃かった月 | `buckets.unit` に応じて 月 / 年 |
| 締めのスライド | また来年も、ふたりのあしあとを。 | これからも、ふたりのあしあとを。 |
| 総集編ページの見出し | `2026年のあしあと` | `沖縄旅行のあしあと` |
| 総集編ページの日付行 | なし | `formatDateLine(period)` を小さく添える |
| 「本物の地図でこの年を見る」 | 現状のまま | 「本物の地図でこの期間を見る」 |

`goToRealMap` は年ではなく period を受け取り、フィルタの from / to に `period.start` / `period.end` を入れる。`kind === 'all'` はモード「全部」にする。

## ポスター

中央の見出しを period に応じて描き分ける。統計行（おでかけ◯日・訪れた場所◯か所・写真◯枚／付き合って◯日目）と左上の「あしあと」ロゴは変更しない。

| kind | 見出し | 副題 | 日付行 |
|---|---|---|---|
| `year` | `2026`（240px 固定、現状のまま） | `年のあしあと` | なし |
| `all` | `これまで` | `のあしあと` | `2024.5.10 〜 2026.8.25` |
| `range` | `沖縄旅行` / `3/1〜3/5` | `のあしあと` | `2026.3.1 〜 3.5` |

日付行は副題のさらに下に、副題より一段小さく・薄く置く（30px / 白 40%）。

### 見出しの寸法決め

文字数が可変なので、描画前に幅を測って詰める。純粋関数 `planHeadline(label, measure)` として切り出し、`measure(text, size)` を注入することで Node からテストできるようにする（canvas 無しで検証したいため）。

- 使える幅は `W - 160 = 920px`
- 1行で `measure(label, 240) <= 920` に収まるならそのまま240px
- 収まらなければ `size = floor(240 * 920 / measure(label, 240))` に縮め、72px を下限とする
- 縮めた結果が120pxを下回り、かつ label に `〜` を含む場合は `〜` の前で2行に割る。2行目は `〜` から始める。各行を920pxに合わせ、小さい方のサイズを両行に使い、下限72px・上限200px
- `〜` を含まないラベルは折り返さない。10文字上限があるため、最悪でも92px程度に収まる

分岐の条件は `〜` の有無だけで、自動生成かユーザー入力かは見ない。自動生成の日付ラベルが主な対象だが、ユーザーが `〜` を含む文字を入れた場合も同じ規則で折り返す。

### 共有ファイル名

`ashiato-<safe>.png`。`safe` は `period.label` からファイル名に使えない文字（`\ / : * ? " < > |` と制御文字）を `_` に置換したもの。置換後が空になる場合は `ashiato-period.png`。共有シートのタイトルは `<label>のあしあと`（year は既存どおり `2026年のあしあと`）。

### 写真の収集

`yearPhotoUrls(year)` を `periodPhotoUrls(period)` に変え、日付範囲で絞る。日付昇順という前提（ポスターが期間内に散らして選ぶために必要）は維持する。総集編ページの写真グリッドも同じ絞り込みに揃える。

## 年末カード

`maybeShowYearEndCard()` は暦年の機能なので、表示条件・文言ともに変更しない。内部で `computeYearReview` を呼んでいる箇所を `computePeriodReview(all, makeYearPeriod(y), ...)` に置き換えるだけにとどめる。

## テスト

**`review-stats.js._selfTest()` に追加**（既存23件に足す形）：

- `makeRangePeriod` のラベル自動生成（同年 / 年またぎ / ラベル指定あり）
- `formatDateLine` の年省略（同年 / 年またぎ）
- `bucketize`：366日以内は月刻み・超えたら年刻み、またぐ月だけ並ぶこと、1バケットなら `busiest` が null
- 年の期間で既存の期待値がそのまま通ること（`monthlyCounts` 相当が12個・`busiest` が7月）＝リグレッション確認
- `newPlaces` の日付判定：年をまたいで初訪問した場所が、月単位の期間でも正しく新規／再訪に分かれること
- `daysTogether`：期間終了日が過去なら終了日基準、現在進行中なら today 基準、期間が記念日より前なら null
- `planSlides`：`range` で件数1件でもスライドが出ること、バケットが1つなら `busiest` のスライドが落ちること

**`review-poster.js._selfTest()` に追加**：

- `planHeadline`：短いラベルは240px単行、長いラベルは縮む、下限72px、`〜` 入りの長いラベルは2行に割れて2行目が `〜` で始まる、`〜` 無しは折り返さない
- ファイル名のサニタイズ

Node での実行は既存どおり `global.window` と `global.App` の両方を用意すること（モジュールが素の `App` を参照するため）。

UIとポスターの見た目は実機または実Chromeで確認する。プレビュー用ブラウザは Google のベクター地図を描画できないため、地図を含む画面の確認には使えない。ポスターは生成した画像を実際に目で見て確かめる（ピクセル値の測定だけでは見落とす）。
