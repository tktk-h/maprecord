# 設計：ふりかえりの画像保存・共有（年間ポスター）

- 日付: 2026-08-24
- 位置づけ: [2026-08-19-year-in-review-design.md](2026-08-19-year-in-review-design.md) で **v1見送り**とした「画像として保存/SNS共有」を実装する。
- 方針転換の記録: 元の仕様書は「自分だけの地図・控えめ方針」を理由に見送っていた。今回は用途を**「彼女に共有するくらい」**に限定したうえで実装する。外部公開を想定した機能ではない。この前提が、下記「入れない情報」の判断根拠になっている。

## 0. 前提となる修正：「おでかけ」の数え方を直す

**ポスターより先に、既存のふりかえりの集計を直す。** ポスターはこの数字をそのまま載せるため、先に正しくしないと誤りをそのまま画像にして配ることになる。

### 現状の誤り

`computeYearReview` の `count` は `yearRecs.length`、つまり**記録（ピン）の本数**。これを総集編ヘッダーで「おでかけ ◯回」と表示している（[js/review-ui.js:378](../../../js/review-ui.js)）。同じ日に3か所まわると「3回のおでかけ」になり、実態と合わない。

### 直しかた

| 名前 | 意味 | 備考 |
|---|---|---|
| `outingDays` | **新設**。その年に記録がある「日」の数（`date` の重複を除いた数） | これが「おでかけ」 |
| `count` | 記録（ピン）の本数。**意味は変えない** | これが「訪れた場所（延べ・単位はか所）」 |
| `monthlyCounts` | **意味を変える**。月ごとの「おでかけ日数」（従来はピン本数） | 「おでかけ」の定義を全体で揃えるため |
| `busiestMonth` | `monthlyCounts` 由来なので自動的に「おでかけ日数が最多の月」になる | 単位が「回」→「日」に変わる |

`isEmpty` / `isSparse` は従来どおり `count` を基準にする（データの有無の判定であり、表示単位の話ではないため）。

### 表示の変更

| 場所 | 現状 | 変更後 |
|---|---|---|
| 総集編ヘッダー | `おでかけ 42回` | `おでかけ 28日` と `訪れた場所 42か所` の**両方**を出す |
| 月別グラフ見出し | `月別のおでかけ` | 据え置き（中身が日数になるので見出しは正しくなる） |
| 月別グラフの棒 | ピン本数 | おでかけ日数 |
| いちばん濃かった月（スライド） | `この月だけで ◯回` | `この月だけで ◯日` |
| 思い出カード | `◯回のおでかけ` | `◯日のおでかけ`（`outingDays` を使う） |
| スライドショー（既存 `places`） | `今年訪れた場所` ＋ `◯回` | `今年訪れた場所` ＋ `◯か所`。単位を「回」から「か所」に統一（下記） |
| スライドショー | — | **「ふたりで過ごした日」スライドを新設**（`outingDays` を大きく表示） |

### 「訪れた場所 ◯か所」の数え方（意図的な選択・変更しないこと）

表記は **「訪れた場所」＋単位「か所」**、値は **`count`（ピンの本数）** を使う。

**これは重複を除いた場所数ではない。** 同じ店に3回行けば3か所として数える。厳密には「延べ場所数」であり、実際に足を運んだ場所の種類数はこれより少なくなる。

この不一致はユーザーが承知のうえで選んだもの。読んだときの語感を優先している。**「か所」と数が合っていないように見えても、バグではないので直さないこと。**

検討して**不採用にした案**: 「訪れた回数 ◯回」（数と単位は厳密に一致するが、語感が硬いため見送り）。

重複を除いた実場所数が必要になった場合は、`coordKey`（`js/records.js` と同じ丸め方）で重複を除いて別フィールドとして足す。既存の `count` の意味は変えない。

スライドの並び順は既存の `days`（付き合って◯日目）の直後に新スライドを入れる。両方とも「日数」の話なので流れが自然になる。

## 1. 何を作るか

総集編ページの末尾から、その年のふりかえりを **1枚の縦長ポスター画像**として書き出し、共有シートに渡すか端末に保存できるようにする。

**「おしゃれであること」が最優先要件**（ユーザー明言）。情報量よりも見た目を優先する。

### 入れる情報

- 年号（主役・中央大）
- おでかけ日数 / 訪れた場所（か所） / 写真枚数
- 付き合って◯日目（記念日が設定されている場合のみ）
- その年の写真（背景タイルとして）

### 入れない情報（意図的に除外）

- **店名・場所名**（ベスト3、いちばん行った場所、最初/最後のおでかけを含む）— 画像は端末外に出るため、行動範囲が特定される情報は載せない。ユーザーの選択。
- **地図・ピン** — 当初案では散らしたピンを入れる予定だったが、意味の読み取れない模様に見えるとの判断で不採用。
- **はじめての場所の数** — 数字が多いと下部が詰まって見えるため不採用。総集編ページには従来どおり残すので、`newPlaces` 自体は削除しない。
- ジャンル別グラフ、月別グラフ — 情報過多で「おしゃれ」から遠ざかるため不採用。

## 2. 見た目の仕様

キャンバスは **1080×1920（9:16）、PNG**。以下は 1080幅を基準にした値。

### 背景

1. その年の写真から選んだ15枚を **3列×5行**のタイルとして敷き詰める（各タイル 360×384、`object-fit: cover` 相当のトリミング）。
2. 全体に **約8px相当のぼかし**をかける（下記「ぼかしの実装」参照）。タイルの継ぎ目を溶かし、中央の年号を読みやすくするのが目的。ぼかしすぎると写真である意味が失われるため、この強さを上限とする。
3. 上から `rgba(38, 26, 19, 0.55)` の暗幕を重ねる。ぼかしを入れたぶん、ぼかし無し案の `0.6` より薄くして写真の色を残す。

### 前景（すべて中央揃え、文字色は白系）

| 要素 | 位置(y) | 指定 |
|---|---|---|
| `あしあと` | 左上 (60, 60) | 12px相当・字間 .24em・`rgba(255,255,255,.85)`・左揃え |
| 年号（例 `2026`） | 約 31% | 約152px・ウェイト300・`#fff`・行高 .86 |
| `年のあしあと` | 年号の下 | 約18px・字間 .3em・`rgba(255,255,255,.8)` |
| 区切り線 | 下部 | 幅52px・高さ1px・`rgba(255,255,255,.4)` |
| 数字1〜2行 | 最下部 | 約18px・行高 1.95・`rgba(255,255,255,.88)` |

数字の並び（各行）:

```
おでかけ 28日 ・ 訪れた場所 42か所 ・ 写真 128枚
付き合って 830日目        ← anniversary が null なら この行ごと省く
```

数字を1行にまとめ、「付き合って◯日目」だけを独立させる。この行が感情的にいちばん効く一文なので、他の数字と混ぜず単独で置く。

`daysTogether` が `null` のときは2行目を出さない。1行だけになるが、区切り線から下の塊は**下端からの位置を変えない**（レイアウトを固定し、上方向の余白として残す）。

### ぼかしの実装（重要）

`ctx.filter = 'blur(8px)'` は **使わない**。iOS Safari で長く未対応だった経緯があり、対応状況によっては「ぼけない画像」が生成され、端末によって仕上がりが変わる。

代わりに **縮小→拡大**で実現する:

1. 1/8サイズ（135×240）のオフスクリーンcanvasにタイルを描く
2. `imageSmoothingEnabled = true` `imageSmoothingQuality = 'high'` で本番canvasへ拡大描画

補間により自然なぼけが得られ、全端末で同じ結果になる。処理も軽い。`ctx.filter` が使える端末で分岐することは**しない**（端末差を作らないため）。

## 3. 写真の選び方

`pickPosterPhotos(photoUrls, n)` — 純粋関数、`n = 15`。

- **均等に間引く**: 先頭から15枚取ると1〜2月の写真ばかりになる。年内の全枚数から等間隔にインデックスを取り、1年に散らす。呼び出し側は日付順に並べた URL 配列を渡す。
- **15枚未満のとき**: 繰り返して15枠を埋める。ただし**同じ写真が上下左右で隣り合わないよう**、繰り返し時にオフセットをずらす。1枚しかない年は全面同じ写真になるが、ぼかしがかかるため破綻しない。
- **0枚のとき**: タイルを描かず、暖色のグラデーション背景にフォールバックする（当初案③の色面）。数字だけで成立させる。

## 4. ファイル構成

`js/review-ui.js` は既に482行あり、これ以上責務を増やさない。**`js/review-poster.js` を新設**する。

- **`js/review-poster.js`** — 「データ → PNG Blob」だけを担う。UI・DOM操作・共有処理は持たない。
  - `App.reviewPoster.build(data, photoUrls)` → `Promise<Blob>`
  - 純粋関数 `pickPosterPhotos(urls, n)`、`statLines(data)`（表示する数字行の配列を返す）、`tileRects(w, h, cols, rows)` を持ち、`_selfTest()` で検証する（`js/review-stats.js` と同じ流儀）。
  - `window.App.reviewPoster` に公開。
- **`js/review-ui.js`** — 総集編末尾にボタンを追加し、`build()` を呼んで結果を共有/保存に渡すだけ。
  - `build()` に渡す URL 配列は**日付昇順に並べてから渡す責任がある**。`App.records.getAll()` の並び順は保証されていないため、その年のレコードを `date` で並べ替えてから写真URLを取り出すこと。並べ替えを忘れると「均等に間引く」が意味を成さない（バグとして表に出にくいので注意）。
- **`index.html`** — `<script src="js/review-poster.js?v=VER">` を追加（`?v=` により Service Worker の版キャッシュに自動で乗る）。
- **`style.css`** — ボタンのスタイル。

## 5. 保存と共有

`js/review-ui.js` 側の責務。

1. `navigator.canShare && navigator.canShare({ files: [file] })` が真なら `navigator.share({ files, title })` を呼ぶ（LINE等へ直接送れる）。
2. 偽、または `share()` が失敗したら **ダウンロードにフォールバック**（`js/backup.js` の `exportJson` と同じ `<a download>` 方式）。
3. ユーザーが共有シートを閉じた場合（`AbortError`）は**何もしない**。エラー表示もダウンロードもしない — 意図的なキャンセルなので。
4. ファイル名は `ashiato-2026.png`。

生成中はボタンを `disabled` にして「作成中…」に変え、二重押しを防ぐ。完了・失敗のどちらでも元に戻す。

## 6. 入口

総集編ページ（`showPage`）の末尾、既存の内容の下にボタンを1つ置く。スライドショー側には置かない（見終わってじっくり読む場所に置くのが自然、という判断）。

## 7. エラー処理

| 事象 | 挙動 |
|---|---|
| 写真1枚の読み込み失敗 | その枠だけ暖色で塗り、全体は続行する。1枚の失敗で機能全体を止めない |
| 全写真が読み込み失敗 | 0枚のときと同じ色面フォールバック |
| `toBlob` が失敗 | `alert` で「画像を作れませんでした」と伝え、ボタンを戻す |
| 共有非対応 | ダウンロードにフォールバック（エラー扱いしない） |
| 共有キャンセル | 何もしない |

### CORS（実装時の要注意点）

写真は Firebase Storage の HTTPS URL。**`img.crossOrigin = 'anonymous'` を必ず設定する。** 忘れると canvas が汚染され、`toBlob()` が `SecurityError` で失敗する（描画自体は成功するので、書き出しの瞬間まで気づけない）。

バケット側の CORS 設定は**不要**であることを実測で確認済み: `firebasestorage.googleapis.com` は `Access-Control-Allow-Origin: *` を返す。

### フォント（実装時の要注意点）

canvas は**読み込み済みのフォントしか使えない**。未ロードのまま描くと日本語が既定ゴシックにフォールバックし、アプリと別物の見た目になる。描画前に以下を待つ:

```js
await document.fonts.load('300 152px "Zen Kaku Gothic New"');
await document.fonts.load('400 18px "Zen Kaku Gothic New"');
await document.fonts.ready;
```

## 8. テスト方針

`_selfTest()` で検証する（node に `window` シムを噛ませて実行できる）:

**`js/review-stats.js`（§0の修正ぶん）** — 既存の `_selfTest` に追加:

- `outingDays`: 同じ日に3件 → 1日として数える / 3日に1件ずつ → 3日 / 0件 → 0
- `count` が従来どおり記録本数のままであること（`outingDays` と別物だと分かるケースで確認）
- `monthlyCounts`: 同じ月の同じ日に複数件あっても1日として数える / 月をまたぐケース
- `busiestMonth` が日数ベースになっていること（ピン本数最多の月と、おでかけ日数最多の月が**食い違うデータ**で確認する。ここが一致するデータだけで試すと、直っていなくてもテストが通ってしまう）

**`js/review-poster.js`（新規）**:

- `pickPosterPhotos`: 30枚→15枚が均等間隔で選ばれる / 15枚ちょうど→そのまま / 5枚→15枠が埋まり隣が重複しない / 0枚→空配列
- `statLines`: `daysTogether` が null のとき1行だけ返る / 非nullのとき2行返る / 1行目におでかけ日数・訪れた場所・写真枚数が別々の値として並ぶ / **「はじめての場所」が含まれない**
- `tileRects`: 3×5で15個の矩形が返り、隙間なく敷き詰められる（合計面積＝キャンバス面積）

canvas 描画そのものと共有処理は自動テストできないため、実機で確認する:

- 写真がある年・ない年の両方で画像が生成される
- 生成された画像でフォントが正しい（日本語がアプリと同じ書体）
- ぼかしがかかっている（端末を変えても同じ見た目）
- iPhone で共有シートが開き、LINEに送れる
- PC でダウンロードされる
- 記念日未設定のスペースで「付き合って」行が出ない
- **§0の修正ぶん**: 同じ日に複数か所まわった年で、総集編の「おでかけ◯日」が「訪れた場所◯か所」より小さくなっている（両者が同じ値のままなら直っていない）
- 月別グラフの棒が日数になっている（1日に3件ある月の棒が3ではなく1ぶん伸びる）
