# 旅行のふりかえり Design

**日付:** 2026-08-30 / **版:** 20260827s（実装時に上げる）

## 何をする機能か

ふりかえりの期間ピッカーに「旅行」を足し、**登録済みの旅行をひとつ選ぶと、その旅行の総集編が開く**ようにする。
見出しは「京都旅行のあしあと」になり、下に「2026.3.1 〜 3.5」の日付行が出る。

## なぜ必要か

旅行（[docs/handoff/2026-08-29-changes.md](../../handoff/2026-08-29-changes.md)・`c3bc867`）は
**カレンダーと記録にしか繋がっていない**。`App.trips` を見ているのは
`app.js` / `calendar.js` / `records.js` / `trip-edit.js` だけで、
**ふりかえりにも絞り込みにも旅行の概念が無い**。
「日をまたぐまとまり」を作ったのに、そのまとまりを**ふりかえれない**のが片手落ちだった。

## 設計の核心：新しい経路を作らない

旅行は「名前＋日付の範囲」でしかなく、ふりかえりは期間 `{kind, start, end, label}` を受け取る。
**この2つはすでに同じ形をしている。** だから変換を1行書くだけでよい。

```js
App.reviewStats.makeRangePeriod(trip.start, trip.end, trip.label)
```

旅行は `kind:'range'` として**既存の期間ふりかえりの道をそのまま通る**。
スライドショー・統計・ポスター・「本物の地図で見る」・戻るバーの×は、いずれも手を入れない。

### ただで手に入るもの（コードを読んで確認済み）

| 欲しいもの | どこが既にやっているか |
|---|---|
| 見出し「京都旅行のあしあと」 | `review-ui.js:532` が `label + 'のあしあと'`（年だけ `'年のあしあと'`） |
| 日付行「2026.3.1 〜 3.5」 | 名前を渡すと `autoLabel:false` になり `formatDateLine` が出す（`review-stats.js` の `dateline-kept-when-user-labelled` が保証） |
| 地図への着地・絞り込み・× | 期間ふりかえりの既存経路（`kind:'range'`） |

## 変更する場所

**`js/review-ui.js` の `showPicker()` だけ。**

`期間を選ぶ`（`.rv-range-open` → `.rv-range-form` を `hidden` トグル）と**同じ折りたたみパターン**で、
「旅行」ボタン（`.rv-trip-open`）と一覧（`.rv-trip-list`）を足す。位置は年ボタン群の下、`期間を選ぶ` の隣。

- 一覧の中身は `App.trips.list` を**開始日の新しい順**に並べたもの（最近の旅行が上）。
  1行に旅行名と日付を出す。
- 押したら上記の `makeRangePeriod` を作って既存の `open()` に渡す。

### 決めた細部

- **旅行が0件のときは「旅行」ボタンを出さない。** 押しても空の一覧しか出ないため。
  （記録が0件のときにピッカー全体が別画面になるのと同じ考え方）
- **記録が0件の旅行は開かず理由を出す。** 期間フォームの既存チェックと同じ文面の作りで
  「この旅行の記録はまだないみたい」。空の総集編を見せない。
- 一覧はピッカーの中に開く。新しいオーバーレイは作らない（`z-index` と閉じる処理が増えるだけ）。

## 触らないもの

`js/filters.js` / `js/review-poster.js` / `js/trips.js` / `js/calendar.js`

`js/review-stats.js` は**ロジックを変えない**（`makeRangePeriod` をそのまま使う）。自己テストだけ足す。

**絞り込みパネルに旅行は足さない。** 旅行で地図を絞るのは
**カレンダーの旅行チップですでにできている**（`calendar.js:111`）。
同じことをするボタンが2か所にあると、どちらを押すべきか迷う。

## 気をつけること

1. **旅行名は20文字まで**（`trip-edit.js:111`）だが、手入力の見出しは10文字まで（`.rv-f-label`）。
   **この経路だけ長い文字列がヒーロー見出し（`.rv-hero-sub`）に来る。** 20文字で崩れないか実機で見る。
2. **旅行名はユーザー入力なので `esc()` 必須。** ジャンル編集と同じ罠（`maprecord-editable-genres`）。
   一覧の行にも、見出しにも通る。

## どう確かめるか

- `review-stats.js` の `_selfTest` に「旅行→期間」の変換を足す
  （旅行の名前が `label` に入ること、`autoLabel` が false になること）。
- **本番の旅行は0件**（2026-08-30 実測）。見え方は**旅行を1件登録して本人のスマホで確認**するしかない。
  エージェント側からは Google ログインとライブ Maps が必要なUIを動かせない。
