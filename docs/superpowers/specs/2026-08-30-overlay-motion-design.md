# 画面が出るときの動きを揃える Design

**日付:** 2026-08-30 / **版:** 20260827z

## 何をする変更か

全画面で出る7つの画面を、パッと現れるのではなく**下から滑り出す**ようにする。
出し入れの作法を `js/overlay.js` にまとめ、各所に散らばった `hidden` の直の付け外しをそこへ寄せる。

## なぜ必要か

本人の言葉:「ほとんどのボタンを押したときにぱっと画面が切り替わるからそれが嫌だ」。

いまアプリの中で**滑らかに出るのは下シート（`App.sheet`）だけ**。残りは一瞬で現れる。
片方だけ丁寧に動くので、かえってちぐはぐに見える。

## 対象の7画面

| 画面 | 要素 | z-index | 種類 |
|---|---|---|---|
| ふりかえり（ピッカー） | `#review-picker` | 60 | 全面 |
| ふりかえり（スライド） | `#review-show` | 60 | 全面 |
| ふりかえり（ページ） | `#review-page` | 60 | 全面 |
| ポスタープレビュー | `#poster-preview` | 60 | 全面 |
| まとめて追加 | `#bulk-overlay` | 1000 | 全面 |
| 設定 | `#settings-panel` | 61 | 幕＋カード |
| ジャンル編集 | `#genre-editor` | 62 | 幕＋カード |
| 旅行編集 | `#trip-editor` | 62 | 幕＋カード |
| 写真のライトボックス | `#lightbox` | 2000 | 幕＋写真 |

**下シート（`#panel`）は触らない。** 既に自前のアニメーションを持っている。

## 動きは2種類

**全面タイプ**（`--bg` や `#f4ece4` で塗りつぶし）は、全体を下から持ち上げる。

**幕＋カードタイプ**（`rgba(...)` の半透明の幕の上にカードが乗る）は、
**幕はフェードし、カードだけが下から**。幕ごと持ち上げると、暗い幕が下からせり上がってきて変に見える。

**⚠️カードの移動距離を「画面の高さぶん」にはしない。** カードタイプの器は `overflow: auto` を
持っており、中身を画面の高さぶん下へずらすとスクロール領域が伸びて、開いた瞬間にスクロールが
跳ねることがある。**24px 持ち上げる程度に留め、幕のフェードと合わせて「下から出た」と感じさせる。**
物足りなければ数字ひとつで変えられる。

## 仕組み: `js/overlay.js`

いまは `app.js` / `bulk.js` / `genre-edit.js` / `lightbox.js` / `review-ui.js` の各所で
`hidden` を直接触っている。同じ処理を7回書けば必ずどれかズレるので、1箇所にまとめる。

```
App.overlay.open(el)          … 出す
App.overlay.close(el, done)   … しまう。done は閉じ終わってから呼ばれる
```

**やること**:
- `open`: 予約を取り消し → `hidden=false` → **次のフレームで** `.ov-open` を付ける
- `close`: 予約を取り消し → `.ov-open` を外す → 動きの時間だけ待って `hidden=true` → `done()`

**⚠️`transitionend` は使わない。** 幕タイプでは動くのが中のカードなので、どの要素で発火するかが
場面によって変わる。中のボタンの色替えなど別の transition を拾って早く終わる事故もある。
**CSSに書いた時間を読んで、その時間だけ待つ**ほうが確実（`transitionDuration` が 0 なら待たずに終える
＝「動きを減らす」設定と広い画面がこれで自動的に処理される）。

**⚠️`done` が要る理由**: `review-ui.js` は閉じるときに `host.innerHTML = ''` で中身を捨てている。
**先に捨てるとスライドの途中で画面が空っぽになる。** 捨てるのは閉じ終わってから。

**⚠️連打**: 出ていく途中で開き直したとき、前の「隠す」予約が後から発火して
開いたばかりの画面を消してしまう。開くときに必ず予約を取り消す。

## カレンダーも寄せる

`js/app.js` に手書きした地図↔カレンダーの出し入れ（`slideCalendarIn` / `slideCalendarOut`）は、
この仕組みと同じことをしている。**`App.overlay` に寄せて手書きを消す。**
カレンダーは横に動くが、モジュールは向きを知らない（クラスを付け外しして時間だけ待つ）ので、
CSS 側が横のままでよい。クラス名は `.showing` から `.ov-open` に揃える。

## CSSの規則

```
.ov-slide            … 全面タイプ。translateY(100%) → 0
.ov-fade             … 幕。opacity 0 → 1
.ov-fade > .ov-card  … 幕の上のカード。translateY(24px) → 0
```

いずれも `.ov-open` が付いたときに定位置へ。速さは 0.32秒／`cubic-bezier(.32,.72,0,1)` で、
地図↔カレンダーやタブの下地と同じ値を使う。**アプリ全体で動きの手触りを1つにする。**

「動きを減らす」設定では transition を切る。上に書いたとおり、
待ち時間はCSSから読むので、切れば自動的に待たずに閉じる。

## 触るファイル

- `js/overlay.js` — **新規**
- `index.html` — 7つの要素にクラスを足す（`.ov-slide` / `.ov-fade` と中の `.ov-card`）
- `style.css` — 上の規則。既存の各オーバーレイの指定は消さない（位置や色はそのまま）
- `js/app.js`（設定・カレンダー）、`js/bulk.js`、`js/genre-edit.js`、`js/trip-edit.js`、
  `js/lightbox.js`、`js/review-ui.js` — 開閉を `App.overlay` に差し替え

## 塞いでおく穴

**浮きボタン。** `#locate-btn`/`#bulk-btn`（z-index 500）は多くのオーバーレイより上に出る。
今日 `body.editor-open` などで塞いだばかり（[[maprecord-overlay-zindex]]）。
**今回は開閉のタイミングが変わるので、印を付ける・外す位置がずれていないか確認する。**
特に「閉じ終わってから外す」にしないと、スライド中に浮きボタンが顔を出す。

## どう確かめるか

- `js/overlay.js` の待ち時間の決め方は純粋なので、Node で自己テストする
  （CSSの時間が 0.32s なら 320ms 待つ、0s なら待たない）
- CSSの到達点は実ブラウザで `getComputedStyle` を測る（目視で判定しない）
- **アニメーションが実際に滑る様子は測れない**（プレビュー枠で `requestAnimationFrame` が
  発火しないため）。動きの気持ちよさは本人が実機で見る。**速さの調整は入る前提。**
